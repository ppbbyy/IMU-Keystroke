# F 키 기준 3차원 상대 위치 기반 자음 추론 — 설계 · 구현 · 검증

왼손 검지 중위지골 IMU(Arduino Nano 33 BLE, LSM9DS1)로 두벌식 자음 14개를 추론하는 단계를
**학습 없는 기하학적 알고리즘**으로 다시 만들었다. 타격 검출은 그대로 두고(출력이 바뀌지 않았음을 검증),
그 뒤의 자음 후보 추정만 F 키 기준 3차원 위치 + 거리 min/max 범위 + 방향 + 이전 타격 대비 이동으로 바꿨다.
기존 2D 자음 추론(2D 기하 디코더, 학습형 분류기·행 모델·타이밍 모델)은 코드에서 제거했다.

> 모든 수치는 피험자 S01 한 명, 노트북 1대, 센서 1개의 실측 3세션(착용 1 두 세션, 재착용 2 한 세션)에서 얻었다.
> '부착 방향 변경', '다른 IMU'는 실측 데이터를 물리적으로 변환한 **모의**이며 실측을 대신하지 못한다(8장 참고).

## 2. 제안하는 알고리즘의 수학적 원리

### 2.1 좌표계
| 이름 | 축 | 정하는 방법 |
|---|---|---|
| 센서 body **B** | 칩 축 | — |
| 중력 좌표계 **G** | up = F 정지 시 비력 방향, h1 = 세션 기준 body 축의 수평 투영, h2 = up × h1 | 단어마다 F 정지 창(60ms)에서 자동 |
| 키보드 좌표계 **K** | x 오른쪽, y 위 행(Q행 쪽), z 위 | G에서 yaw θ, 손잡이 f, 배율 s 만 남음 |

F 키 = 원점 **(0,0,0)**. 모든 단어는 F 정지에서 시작해 F 정지로 끝난다.

### 2.2 무엇이 미지수인가
센서 부착 방향(3자유도 회전)은 중력이 롤·피치를 정해 주므로 G까지는 **자동**이다. 남는 것은
`K = s⁻¹ · R(θ) · diag(1, f) · G_h` 의 **세 숫자 θ, f∈{±1}, s** 뿐이다(+ 자이로 부호 규약 3비트).
이것들은 모델 파라미터가 아니라 **좌표계 정렬값**이고, 세션의 라벨 없는 타이핑으로 그때그때 추정한다(5장).

### 2.3 타격 사이 변위와 루프 닫힘
타격 j−1 → j 구간에서 선형가속도 `a(t) = R(t) f(t) − g₀` 를 적분하되, 타격 순간 손가락은 키 위에서 멈추므로
**구간 끝 속도 = 0**(ZUPT)을 선형으로 강제한다 → 구간 변위 `d_j`. 상수 가속도 바이어스는 이 선형 보정으로 정확히 사라진다.

F→…→F 이므로 `Σ_j d_j = 0` 이어야 한다. 실제 남는 닫힘 오차 `E = Σ d_j` 를 구간 보정 `c_j` 로 나눠 뺀다:

```
min Σ_j |c_j|² / (q·W_j)   s.t.  Σ_j (d_j + c_j) = 0         ⇒   c_j = −(W_j / Σ W) · E
```
`W_j = T_j³` 는 가속도 백색잡음을 두 번 적분했을 때 위치 분산이 구간 길이의 세제곱으로 자라는 데서 온다
(기존 방식 '시간 비례'는 `W_j = T_j` 인 특수한 경우).

키보드 평면 제약(선택, 기본 켬): 모든 타격이 같은 키 윗면 높이 `z_ref`(미지수) 위에 있다는 약한 관측
`(P_k,z − z_ref)² / σ_p²` 을 같은 최소제곱에 넣는다.

**불확실성.** 닫힘을 걸면 위치 오차는 양 끝이 0인 브라운 다리가 되어
`σ_k² = q · S_k (S − S_k) / S` (`S_k = Σ_{j≤k} W_j`). 잡음 강도 `q` 는 세션의 닫힘 오차들로 라벨 없이 추정한다
(`E|E|² = 3 q S`) — 센서 잡음이 달라도 허용 오차가 자동으로 따라간다.

### 2.4 거리 + 방향 분해
키 c의 중심 μ_c, 관측 위치 p (r = |p|) 에 대해 등방 가우스의 로그 우도는 정확히 두 항으로 갈린다:
```
log N(p; μ_c, σ²I) = −(r − |μ_c|)² / 2σ²   −   r|μ_c| (1 − cos Δθ) / σ²   + const
                      └ 거리(회전 불변) ┘      └ 방향(yaw가 필요) ┘
```
그래서 '거리 min/max 범위 + 방향'은 임의의 조합이 아니라 위치 우도를 극좌표로 쓴 것이다.
방향 항의 집중도는 yaw 추정 불확실성 σ_ψ 를 더해 `1/κ = σ²/(r|μ_c|) + σ_ψ²` 로 둔다 →
정렬을 믿기 어려우면(σ_ψ 큼) 방향 항이 저절로 약해지고 거리 항만 남는다. 가까운 키(r|μ_c| 작음)도 방향이 저절로 약해진다.

## 3. F 키 기준 3차원 상대 위치 추정 방법 (`track3d.py`)

단어 하나(타격 n개)마다:
1. **시작 정지 창**(`motion.find_onset`, 기존 함수) → 중력 `g₀`, 자이로 바이어스 `b`. 끝 F 정지(`features.tail_settle`, 기존)가 있으면 `b` 는 두 창의 평균.
2. **가속도 배율 보정**: `|g₀| = 9.80665` 가 되도록 그 단어 가속도를 스케일 → 센서별 감도 차이 흡수.
3. **회전**: 바이어스를 뺀 자이로를 적분해 `R(t)`(body(t)→body(t₀)). 손가락 회전 중에도 가속도를 기준 프레임으로 옮긴다.
4. **중력 제거**: `a = R f − g₀`.
5. **구간 분할**: 경계 = 시작 정지 → 각 타격 직후 가장 조용한 샘플(기존 규칙을 **시간 단위**로 환산; 233Hz에서 원래와 동일) → 끝 F 정지.
6. **구간 ZUPT 적분** → `d_j` (G 좌표, mm).
7. **루프 닫힘 + 평면 제약**(2.3) → 타격 위치 `P_k`, 이동 `D_k = P_k − P_{k−1}`, `σ_k`, `σ_rel,k`.

출력 `WordTrack`: `P (n,3)`, `D (n,3)`, `sig (n,)`, `sig_rel (n,)`, `closure (3,)`, `z_ref`, `t_strike`.

**실측 확인**(착용 2, 개별 키 840회 F→키→F): 키별 위치 중앙값이 행 간격 19~20mm, 열 간격 19~20mm, 행 엇갈림(ㄱ −0.25u, ㅊ −0.5u, ㅍ +0.5u)까지 재현됐다.
높이 z는 행과 거의 무관(−3 ~ −5mm) → z는 키 구분이 아니라 평면 제약·3차원 거리에 쓴다.

### 3.1 기술적 한계 (반드시 알아야 할 것)
| 한계 | 영향 | 대응 |
|---|---|---|
| 가속도 이중적분 오차는 T^2~T³로 자란다 | 연속 타이핑에서 보정 전 닫힘 오차 중앙값 36~54mm (키 2~3개 폭) | 타격 ZUPT + F→F 닫힘. 닫힘을 끄면 자음 Top-1이 72%→32%로 무너짐(7장) |
| 끝점이 F라는 사실은 **오차의 합만** 알려 준다 | 중간 경로의 오차 모양은 ∝T³ 가정으로 나눌 뿐. 한 구간의 큰 오차(충격·회전 추정 오차)는 다른 구간으로 번진다 | σ_k(브라운 다리)로 불확실성을 점수에 반영 |
| 자이로 드리프트 → 중력 누설 | 상수 기울기 오차는 구간 ZUPT가 제거하지만 시간에 따라 변하는 오차는 남는다 | 단어마다 F 정지에서 바이어스 재추정(시작·끝 평균), 단어 길이 수 초 |
| yaw(중력축 회전)는 관측 불가 | 중력만으로는 '키보드 오른쪽'을 모른다 | 세션 단위 EM 정렬(5장) |
| 센서는 손끝이 아니라 중위지골에 있다 | 위 행으로 뻗을 때 센서 이동 ≠ 손끝 이동, 높이도 변함 | 배율 대역 [0.8, 1.2], 키캡 산포, σ로 흡수 |
| 연속 타이핑 위치 오차 σ ≈ 10mm ≈ 0.5u | **F 거리 구간만으로는 후보가 거의 줄지 않는다**(평균 13/14) | 거리는 게이트, 최종 후보는 3D 영역 점수의 누적 90% 집합(평균 2.6~3.4개) |
| 타격 누락·추가 | 구간 분할 자체가 틀린다 | 기존 검출의 한계를 그대로 받음(타격 수 일치 90~98%) |

**정확한 3차원 궤적 복원은 IMU만으로 불가능**하다는 전제에서, 이 방법은 '각 타격의 F 기준 위치를 키 칸 정도의 정확도로'
추정하고 그 불확실성을 정량화해 사전·이웃 타격 정보와 결합하는 것을 목표로 한다.

## 4. 자음별 min/max 범위 설정 방법 (`keymap3d.py`)

### 4.1 정의
* 키 칸 = 중심 ± pitch/2 (손가락은 키 윗면 어디든 칠 수 있음), 높이 z_ref ± z_env/4
* `d_k` = F에서 칸 중심까지 3차원 거리
* `r_min,k / r_max,k` = F에서 칸(3차원 상자)까지 최소 / 최대 거리 (F 자신은 0)
* `d_min,k = max(0, s_lo·r_min,k − m·σ)`, `d_max,k = s_hi·r_max,k + m·σ`
  * `s_lo, s_hi = 0.8, 1.2` : 배율 오차(센서 위치·적분)
  * `σ` : 그 타격의 추정 σ_k (track3d), `m = 2` (≈95%)

**임의 상수가 아니라** '칸 크기(물리 배열) ⊕ 배율 오차 ⊕ 그 타격의 추정 오차'로 정해진다. 이웃 타격 사이 이동 거리의 범위도 두 칸 사이 최소·최대 거리로 같은 방식이다.

### 4.3 정규화(키보드가 달라도)
내부 계산은 pitch 하나로 정해지므로 키 단위(u)로 나누면 키보드가 달라도 같은 표다. 키보드를 바꾸면 **자로 키 10개 폭을 재서 pitch만** 바꾼다.
게다가 배율 s를 세션마다 라벨 없이 추정하므로 pitch를 17.5 / 19 / 20.5mm로 틀리게 줘도 결과가 거의 같았다(7장).

### 4.4 '거리 구간' vs '3차원 영역' 비교

## 5. 자음 후보 선정 및 점수 계산 방법 (`consonant3d.py`, `align3d.py`)

### 5.1 타격별 점수 (sector)
p = 키보드 좌표 위치(정렬 후), σ = σ_k / s:
```
U_k(c) =  ① 게이트   −½ (excess_c / σ)²,  excess = [d_min,c − r]₊ + [r − d_max,c]₊         (F 거리 min/max)
        + ① 순위     −½ (r − d_c)² / (σ² + σ_hit² + (0.1·d_c)²)                         (기준 거리)
        + ② 방향     κ_eff,c (cos(φ_p − φ_c) − 1)                                       (F 기준 이동 방향)
σ_hit² = (키캡 폭 14.5mm)²/12  — 키캡 위 균등 타격의 분산
```
### 5.2 이전 타격 대비 이동 (k ≥ 2)
이동 벡터 Δ = D_k 를 키 a→b 칸 중심 벡터 V_ab 와 같은 방식으로 비교(길이 게이트 [pmin_ab, pmax_ab], 길이 순위, 방향).
`Pair_k(a, b)` (14×14). 같은 키 연타(ㄱㄱ)는 V=0 이라 길이만 본다.

### 5.3 후보·확률
* **사슬 주변확률**(사전 단어 없이): 상태 = 자음, 에너지 Σ U + Σ Pair 의 forward-backward → 타격별 14자음 사후확률.
  선택적으로 사전 텍스트에서 센 자음 트라이그램(`ConsonantLM`, IMU 학습 아님, γ=0.5)을 곱한다.
* **후보 집합**: ① F 거리 대역 안의 자음(회전 불변 게이트) ② 사후확률을 큰 순으로 누적 90%까지(최종 후보군).
* **단어 점수**: `score(word) = Σ_k U_k(c_k) + Σ_k Pair_k(c_{k−1}, c_k) + λ·log 빈도`, λ = 0.5.

### 5.4 정렬(초기 캘리브레이션 ≠ 학습)
| 항목 | 방법 | 라벨 |
|---|---|---|
| 자이로 부호 3비트 | 정지 자세 쌍 사이 중력 방향 변화 vs 자이로 적분 예측(8조합). 중력 축 둘레처럼 애매한 후보는 F 복귀 닫힘이 더 작은 단어가 많은 쪽 | 없음 |
| 배율 s | 관측 평균 F 거리 ÷ 사전 자음 빈도로 본 기대 거리 Σπ_k d_k (회전·거울 불변) | 없음 |
| yaw θ, 손잡이 f | EM: E = 현재 정렬로 사슬 주변확률 γ, M = 가중 Procrustes `θ = atan2(Σγ o×c, Σγ o·c)`. 초기 θ 12개 × f 2개 중 주변 우도 최대 | 없음 |
| yaw 불확실성 σ_ψ | 단어별 θ_w 의 원형 분산 → von Mises κ | 없음 |
| (선택) 탭 | 알려진 키 몇 번 → Procrustes | 수 개 |

EM에서 배율까지 함께 풀면 '모두 F 근처로 줄어 F에 배정 → 더 줄어듦'으로 붕괴했다(s → 1.6). 그래서 배율은 모멘트로 먼저 고정한다.
추정 결과: 3세션 모두 자이로 부호 (−1,−1,−1)(기존에 정답 라벨 일치율로 정했던 값과 같음), 손잡이 −1, θ = 94° / 100° / 78°,
배율 0.96 / 1.04 / 1.07 — 정답 라벨로 구한 θ(92° / 100° / 78°)와 일치.

**구분**: 여기서 추정하는 것은 좌표계를 맞추는 숫자 5개(θ, f, s, 자이로 부호)와 잡음 강도 q 이고, 키 위치·분류기·가중치는 **어떤 센서 데이터로도 학습하지 않는다.**
키 위치는 물리 배열, 점수 형태는 물리 모델, 언어 사전은 텍스트에서 온다. 하이퍼파라미터(배율 대역, m, 키캡 폭, 평면 σ)는 물리량으로 정했고 S01에서 조정한 것은 없다
(영역 모드·가중치 비교만 수행했고 기본값 1을 유지).

## 6. 기존 코드와의 통합 방법

```
IMU 수집 (변경 없음)
  ↓
features.detect_presses [→ features.refine_presses]      ← 기존 타격 검출, 수정 없음
  ↓  det: DataFrame(trial_id, det=타격 시각[s] 배열, …)
track3d.strikes_from_detection(det) → {trial_id: 타격 시각 배열}
  ↓  + 세션 IMU 연속 데이터(타격 사이 구간)
align3d.choose_gyro_sign(sd, strikes)                    ← 센서 좌표계 규약(라벨 없음)
  ↓
track3d.track_session(sd, strikes, TrackParams)          ← 좌표계 정렬(중력), 측정 오차 보정, F 기준 3D 위치
  ↓  [WordTrack(P, D, sig, sig_rel, closure, z_ref, …)]
align3d.fit_alignment(tracks, Scorer3D, lm, prior)       ← yaw·손잡이·배율 (라벨 없음)
  ↓  Alignment(theta, flip, scale, sigma_yaw)
Scorer3D.observe(track, alignment) → Obs3D(U (n,14), Pair (n,14,14))   ← min/max + 3D 영역 + 이동
  ├─ chain_marginals(obs, lm) → 타격별 자음 사후확률(후보·점수)
  └─ decode.Lexicon.rank_words(scorer, obs, λ)           ← 기존 사전 단어 후보 생성·순위
  ↓
최종 한국어 단어
```
한 번에: `infer3d.infer_session(sd, lexicon, lm, prior, Infer3DConfig())` → `Result3D(alignment, gyro, info, words=[WordResult])`.
`WordResult`: `track`, `candidates`(거리 대역 bool), `marginals`(14자음 확률), `words`([(점수, 단어)]), `consonants`(최빈 자음열).

**다른 센서 연결**: `track3d.session_arrays`가 돌려주는 세 배열(시각 s, 가속도 m/s², 자이로 rad/s)만 맞추면 된다. 출력 주기는 시각에서 읽고,
축 순서·부호·손잡이·부착 방향은 정렬 단계가 라벨 없이 정한다.

| ② 부착 방향 변경 | 같은 링을 90°·180° 돌려 착용, 손등/손바닥 쪽 각 1세션(`--wear` 증가, meta.notes에 각도) | 모의 결과(변화 없음)가 실측에서도 성립하는지 |
| ③ 키보드 변경 | 노트북 2종 + 외장(19.05mm) 키보드, 각 1세션. `--pitch`에 실측 키 간격 | pitch만 바꿔 학습 없이 같은 성능인지, 키 깊이·행 높이 차(외장 키보드의 계단형 행)가 평면 가정을 깨는지 |
| ④ 다른 IMU | 예: BMI270/ICM-42688(오른손 축, 출력 주기 200~400Hz)을 같은 위치에. `session_arrays`만 어댑터로 | 자이로 부호·손잡이 자동 추정 성공률, 출력 주기 효과 |
| ⑤ 추가 학습 없이 | 위 모든 세션에서 `--causal 20`(앞 20단어 정렬) | 보고 지표 전부 |

보고 지표: 자음 Top-1·Top-3·Macro-F1, 후보군(누적 90%) 정답 포함률·크기, 단어 Top-1/3/5(어휘 크기별), 조건 변경 전후 차이(Δ, 세션 부트스트랩 95% 구간),
캘리브레이션에 쓴 데이터(단어 수·라벨 수)와 시간. 기존 방식은 git `3315786`의 `pipeline_test.py`로 학습 세션 고정·시험 세션만 바꿔 같은 표를 채운다.
피험자를 늘릴 때(≥5명)도 같은 표에 사람 간 분산을 더한다 — 이번 결과는 한 사람의 것이다.

```
python scripts/eval3d.py <세션들>                     # 기본(IMU만, 세션 전체 EM)
python scripts/eval3d.py <세션들> --causal 20         # 앞 20단어로만 정렬
python scripts/eval3d.py <세션들> --strikes keylog    # 오라클 타격(검출 오차 분리)
python scripts/eval3d.py <세션들> --pitch 19.05       # 다른 키보드
python scripts/eval3d.py <세션들> --perturb mount|sensor   # 모의
```

### 8.3 남은 과제(정직하게)
* 단어 Top-1 20~32%는 아직 실사용 수준이 아니다. 오차의 큰 부분은 연속 타이핑 위치 σ ≈ 10mm 이다.
  개선 후보: 타격 직후 '키 누름 유지' 구간을 더 길게 정지로 쓰기, 자력계 조건부 yaw 보정(기존 magnet.py) 재검토, 단어 끝 복귀 경로의 형상 이용.
* 낮은 출력 주기(119Hz)에서 −6~7%p. 200Hz 이상 권장(기존 QwertyRing 근거와 일치).
* 정렬 EM은 세션 안에서 손 yaw가 거의 일정하다고 가정한다(σ_ψ 7~10°로 실측). 자세를 크게 바꾸면 다시 맞춰야 한다(라벨은 여전히 불필요).
